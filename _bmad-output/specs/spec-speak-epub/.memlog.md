- (decision) Why: readers need offline EPUB first, audiobook second for web-fiction (NovelPhoenix) but no export and scrapers fail on noisy HTML and bans after 4-5 fetches; existing Speak EPUB solves EPUB->audio via Edge TTS
- (capability) CAP-1 Find: intent — reader can find novel by pasting URL or typing title and seeing per-site matches with chapter counts to pick source; success — title search returns correct matches with chapter counts per site in <5s, fallback guesses site for unknown URL
- (capability) CAP-2 Choose: intent — reader can fetch chapter list politely and pick exact range via from-to plus checkboxes; success — list loads with polite indication, range 1-30 selects exactly 30 of 142 and syncs checkboxes
- (capability) CAP-3 Fetch & Clean: intent — system can fetch only chosen chapters politely with cache/resume and isolate body via per-adapter selectors plus heuristic fallback with preview-correctable bounds and strip user filters; success — 100-chapter novel scrapes without 429/ban, preview isolates body >95% without manual fix, bounded resume fetches only missing, open-ended re-validates for new chapters
- (capability) CAP-4 Build EPUB: intent — system can assemble validated EPUB (title/author/cover/TOC) as standalone artifact with filters applied once at build; success — 20-chapter sample epubcheck clean, 0 subscription-nag lines after filters, cover and TOC correct
- (capability) CAP-5 Make Audio: intent — system can turn EPUB into chapter MP3s and single M4B/M4A with chapter markers using sentence-boundary chunking and global parallel queue; success — 10-chapter sample builds M4B with correct markers in <1h on parallel 3 via reused PartJob pipeline
- (capability) CAP-6 Control & Persist: intent — reader can see live per-chapter and per-part progress with logs and throttle tier and persist all settings across restarts; success — queue shows queued/fetching/TTS/merging/done with resume badge, Settings and Filters persist, keep switches control EPUB/MP3/M4B outputs
- (constraint) Politeness: sequential fetch with 3-5s jitter default, 10s safe, adaptive backoff on 429, cache raw HTML, no parallel scrape even though TTS parallel 2-3 is allowed
- (constraint) Local-first: zero data leaves device after fetch; offline after fetch must work for preview/EPUB/M4B; single desktop artifact Win/macOS/Linux via Tauri
- (constraint) Brownfield: reuse speak.py split_text_for_tts max 3500 sentence boundary, PartJob global queue, FFmpeg/ffprobe required for M4B, spine-order numbering, skip <100 chars, venv at Speak-EPUB-1.0.0/venv per AGENTS.md
- (constraint) Architecture: Modular Pipes-and-Filters + Ports & Adapters (AD-1..AD-10), single event bus, EPUB as intermediate invariant, filter at EPUB stage only, Tauri sidecar via shell [ASSUMPTION]
- (constraint) UX: progressive disclosure — first screen one input plus pick; advanced behind Settings/Filters; schludnie modern neutral palette with accent live
- (constraint) Licensing: MIT per Speak-EPUB-1.0.0/LICENSE.md, community adapter model, no branch protection yet
- (decision) Non-goals: batch queue of multiple novels, logged-session paywall bypass (designed but hidden experimental), auto-update scheduling, cloud sync, mobile companion, >5-site bulk search, collaborative filter sharing, non-Edge TTS engines, DRM
- (decision) Success signal: paste title/URL -> see per-site counts in <5s -> pick range -> get clean EPUB (epubcheck ok, 0 nag lines) and, if chosen, M4B with markers locally without manual cleanup or bans, resume correctly on re-run
