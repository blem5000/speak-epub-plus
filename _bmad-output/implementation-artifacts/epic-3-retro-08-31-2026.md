## Findings

All findings were derived from the diff and re-verified against primary sources before routing.

### Aggregate views

- **[HIGH] fix now — failed-merge path deletes the part files the fallback points at.** In `finalize_chapter_audio` the `if not keep_parts:` deletion block (`Speak-EPUB-1.0.0/core/tts.py:583-589`) sits inside `if has_ffmpeg:` at the same level as the `try/except`, not in the success branch. When `concat_mp3_files` raises (`tts.py:566-581`), the unmerged part entries are appended to `audio_entries` (576-581) and then the same parts are `os.remove`d — `build_m4b` receives entries whose files no longer exist. Verified by direct read.
- **[HIGH] fix now — test masks the above bug.** `tests/test_tts.py:1418-1439` (`test_finalize_concat_failure_fallback`) runs with `keep_parts=False` (line 1435) and asserts fallback entries + warning, but never asserts the part files still exist. Failure path ships green. Verified by direct read.
- **[MEDIUM] fix now — CancelledError leaves truncated MP3s that resume then trusts.** Partial-file cleanup lives in `except Exception` (`core/tts.py:216-224`), but `run_part_jobs` cancels siblings with `task.cancel()` (`tts.py:415-417`); `asyncio.CancelledError` is a `BaseException` in 3.8+, so a worker mid-`communicate.save()` leaves a truncated file the skip guard (`tts.py:339`) treats as done.
- **[MEDIUM] fix now — zero-byte/corrupt parts wedge a chapter permanently.** Skip guard checks existence only (`core/tts.py:339-351`); `finalize_chapter_audio` warns "exists but empty/corrupt" but does not requeue (`tts.py:527-535`). A 0-byte file from a hard kill blocks the chapter until manual deletion.
- **[MEDIUM] fix now (verify first) — FFmpeg concat apostrophe escaping likely wrong.** `core/tts.py:454` and `:641` write `safe.replace("'", "\\'")` inside single-quoted `file '...'` directives; the concat demuxer treats `\` inside single quotes as literal, so the correct escape is `'\''`. `sanitize_filename` (`tts.py:41`) does not strip `'`. Based on documented demuxer grammar, not a real binary run — verify before fixing.
- **[MEDIUM] fix now — two hand-synced `speak.py` copies.** Root `speak.py` and `Speak-EPUB-1.0.0/speak.py` are both tracked, both changed in this range, and commit `40a83c8` actually diverged them (inner got core delegation while root still carried `class PartJob`) until `47fd613` resynced. Nothing (test, CI, build step) enforces the sync.
- **[MEDIUM] fix now — module docstring contract broken in-place.** `core/tts.py:14` declares "Pure: only os/re/dataclasses/pathlib/typing", but lines 19-23 import `asyncio/shutil/subprocess` and 209-212 lazily import `edge_tts`. Stories 3-2/3-3 turned a pure planning module into a mixed I/O module without updating the header.
- **[MEDIUM] defer — `core/tts.py` god-class growth.** Now 725 lines / 12 functions spanning four responsibilities: chunking (67-116), planning, TTS I/O (`tts_text_to_mp3`, `run_part_jobs`), merge/M4B (`finalize_chapter_audio`, `concat_mp3_files`, `build_m4b`). Each commit was small; only the epic-wide view shows it.
- **[MEDIUM] fix now — no cross-process lock on part writes.** The skip guard at `core/tts.py:339` has no locking, so two simultaneous resume runs can both write the same part MP3.
- **Pattern divergence: none beyond the above.** Logging/`print` conventions match the rest of `core/`.
