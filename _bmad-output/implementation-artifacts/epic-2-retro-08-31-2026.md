### Diff-scope review (adversarial / edge-case / verification-gap lenses, delegated; key findings re-verified at source)

* **[fix now — high] Preview XSS via unsanitized scraped HTML.** `src/components/Preview.tsx:424,426` render `originalHtml` (raw page from the novel site) and cleaned/filtered HTML through `dangerouslySetInnerHTML` with no sanitizer — remote `<img onerror=…>` executes in the Tauri webview. No sanitizer exists to test (`Preview.test.tsx` has 8 tests, none cover it).
* **[fix now — medium] Tauri capability expansion unscoped.** `src-tauri/capabilities/default.json:13,20` adds `shell:allow-spawn` and `opener:allow-open-path` with no path/arg allowlist; combined with the XSS above this is a real chain. Related: `tauri.conf.json:26` still `"csp": null` (open epic-1 retro item 5).
* **[fix now — high, SEAM fetch→clean] Cache-hit path bypasses the clean pipeline.** `core/fetch.py:153-185`: a cache hit returns naive whole-page text (only script/style/nav/aside stripped), while a fresh fetch of the same URL returns selector-isolated content via `adapter.fetchChapter` → `core.clean` — the fetch→clean contract differs by cache state, so single-chapter preview/clean on resume differs from a first run.
* **[fix now — medium] Cache poisoning fallback.** `core/fetch.py:217-219` — when `cc.html` is empty, `write_cache(url, str(cc))` persists the Python repr of the `ChapterContent` object as `raw.html`, served forever afterwards as a valid cache hit.
* **[fix now — medium] Retryable classification matches chapter numbers.** `core/fetch.py:238-239` — `is_5xx = re.search(r"\b5\d\d\b", msg)` and `is_429 = "429" in msg` run against the full exception message including the URL: a genuine 404 on `/chapter/500` becomes retryable (5-retry storm), `/chapter/429` on a 403 falsely flips the global throttle tier and emits a bogus `throttleChanged`.
* **[fix now — medium] Error-code mapping by message substring.** `core/config.py:1912-1916` — `"VALUE_ERROR" in msg2` / `"CACHE_MISS" in msg2` misclassify any wrapped exception whose text merely contains those tokens; GUI badge mapping then shows the wrong error.
* **[fix now — medium, SEAM clean→filters→epub] EPUB build silently ignores stored filters on failure.** `core/epub.py:266-286,541-547` — store-load failures collapse to `filters=[]` and per-chapter filter errors fall back to `filtered_html = cleaned_html`; a corrupt store yields an unfiltered EPUB while Preview showed filtered text (Preview surfaces the same error as VALUE_ERROR, `config.py:1323-1325`) — silent preview-vs-product divergence, and it violates the raw-nag/EPUB-clean invariant the epic promised.
* **[fix now — medium] `getEpubStatus` returns the latest EPUB of *any* novel.** `core/config.py:1939-1948` accepts `novelUrl`/`from`/`to` then picks `max(candidates, key=mtime)` across the output dir; two novels built into one output dir can point Result/Open-folder at the wrong book. It also swallows `run_epubcheck` failure as `epubcheck_ok: true` (`:1953-1959`).
* **[defer — low] Cache-key query stripping can collide distinct chapter URLs** (`core/fetch.py:31-53`); consistent with epic-1 open question on paginated drift.
* **[accept — medium] epubcheck proxy admits residual risk** — spec-2-4:196 documents that the XHTML well-formedness check is not the real epubcheck binary; accepted deviation, revisit when bundling epubcheck.
* **Verification gaps** (test inventory vs ACs): no cross-story pipeline test (fetch → preview-selected selectors → filters → buildEpub) on shared fixtures — every test pins one story in isolation; no test that `buildEpub` with a corrupt store still filters (it silently doesn't, see above); `test_buildEpub_keepEpub_reflection` (`test_handle_rpc_epub.py:137`) only pins that `keepEPUB` is *reflected* — nothing pins actual file lifecycle; `getEpubStatus` tested with a single epub only (`test_handle_rpc_epub.py:184`); no unicode/Polish-diacritics EPUB metadata test despite pl.json being first-class; no non-contiguous-selection status-mapping test (`useFetcher.ts:295-309` final sweep unpinned).
